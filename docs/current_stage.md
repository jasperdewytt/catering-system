4. Humans see clear exceptions only when the system reaches safety risk, ambiguity, low-confidence AI interpretation, or operational uncertainty.
5. All automated actions, AI interpretations, accepted-cost decisions, and human interventions remain auditable and reproducible.

The current implemented allocation algorithm remains:

1. For each non-cancelled session, walk the enrolled students minus opted-out, year-excluded, and absent.
2. For each student, pick a safe offered variant given their dietary tags.
3. Aggregate per-session into variant-aware `order_lines`, per-student into `order_allocations`.
4. Reproducibility: the same DB state should always produce the same order_run output.

Final implementation will extend this into a preference-aware, autopilot-owned offer-set and allocation path:

- deterministic safety filters stay first
- dish preference/style tags are separate from safety/dietary flags
- offer-set selection is per caterer, enumeration-first with greedy fallback above `100_000` subsets
- objective is cohort fit with persisted fit debt and bounded exploration, minus caterer-level MOQ/waste cost
- MOQ is a caterer-level floor keyed by `menu_item_count`, not a per-dish floor
- autopilot retries do not double-approve, duplicate snapshots, or double-send
- gates should consume existing validation findings and `order_allocation_issues`, not reimplement validation
